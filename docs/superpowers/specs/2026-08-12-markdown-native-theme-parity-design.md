# Markdown 编辑器原生主题一致性设计

## 目标

让 Markdown 可视化编辑器的代码块在布局、控件、字体、颜色和编辑器配置上与思源原生代码块保持一致，并让 Markdown 编辑器的全部可见组件统一适配思源主题系统，包括浅色主题、深色主题和第三方主题。

## 设计原则

- 原生编辑器是视觉与配置行为的基准，Markdown 编辑器不再维护一套独立的代码块视觉规范。
- CodeMirror 继续负责 Markdown 源文编辑、光标、选择区和装饰器，避免复用 Protyle DOM 后引入事件代理和内容编辑模型冲突。
- 复用思源主题变量、原生元素的计算样式、Highlight.js 主题类名和图标精灵，不复制固定颜色或手写 SVG。
- 主题适配覆盖整个 Markdown 编辑器，不只修复代码块。
- 保留宿主无关边界：`markra-core` 通过配置或 CSS 自定义属性接收思源宿主能力，不直接依赖 Protyle 实例。

## 代码块视觉结构

Markdown 代码块采用思源原生代码块的视觉层级：

1. 代码块容器使用原生主题定义的背景、圆角、字体、字号、行高和内边距。
2. 语言、复制和更多操作位于右上角操作区，默认弱化或隐藏，在代码块悬停、聚焦或键盘操作时显示。
3. 语言选择继续支持 Markdown 编辑行为，但外观改为原生语言操作入口，不显示持续可见的浏览器风格下拉框。
4. 复制、更多、展开等操作使用 `app/appearance/icons/litheness/icon.js` 中已有的思源图标精灵。
5. 不给 Markdown 操作控件使用 `.protyle-action__*` 等原生事件钩子类名，避免被 Protyle 全局事件代理错误处理。
6. 围栏标记仍由 CodeMirror 管理；闭合代码块在所见即所得状态下不额外暴露一套与原生代码块冲突的顶部标签或底部边框。

## 原生编辑器设置同步

Markdown 代码块直接跟随以下全局配置：

- `window.siyuan.config.editor.codeSyntaxHighlightLineNum`：控制行号显示。
- `window.siyuan.config.editor.codeLineWrap`：控制自动换行和长单词折行。
- `window.siyuan.config.editor.codeLigatures`：控制代码字体连字。
- `window.siyuan.config.appearance.codeBlockThemeLight` 和 `codeBlockThemeDark`：选择与原生代码块相同的 Highlight.js 配色主题。

配置在创建 Markdown 编辑器时注入。设置或主题在运行时变化时，主题桥接层刷新 CSS 自定义属性，编辑器配置层重新计算代码块扩展；不要求关闭文档或重启应用。

## 语法高亮一致性

现有 Lowlight 继续负责把代码转换为高亮范围，因为其输出与 Highlight.js 使用相同的 `hljs-*` 类名。Markdown 代码装饰器保留这些类名，并确保装饰节点处于能够命中当前 Highlight.js 主题规则的上下文中。

不得为关键字、字符串、注释等语法类别另设固定颜色。原生 `setCodeTheme` 加载或切换代码主题后，Markdown 代码块应立即获得相同的语法配色。无法识别的语言按原生行为回退为纯文本，不进行自动猜测导致的随机配色。

## 主题桥接

扩展现有 `markdownThemeBridge`，继续通过隐藏的 `.protyle-wysiwyg` 探针读取当前主题的计算样式，并将结果写入 Markdown 编辑器使用的 `--b3-markdown-*` 自定义属性。桥接内容至少包括：

- 编辑器背景、正文颜色、字体、字号和行高。
- 标题、链接、强调、删除线、行内代码和引用。
- 代码块背景、圆角、字体、字号、行高、内边距和次要文字颜色。
- 表格边框、表头背景、行悬停和选中状态。
- 浮层背景、边框、阴影、悬停、焦点和强调色。
- 搜索匹配、脚注、Callout、Mermaid 预览等 Markdown 专用组件需要的语义色。

主题桥接监听思源根节点主题类名、主题样式表和代码高亮样式表变化。更新采用合并调度，避免 MutationObserver 在样式加载过程中重复触发大量布局计算。

## 整个 Markdown 编辑器的样式收敛

审计并替换 Markdown 编辑器中的独立颜色来源，包括 `Canvas`、`CanvasText`、裸 `rgb/rgba`、裸十六进制颜色和基于 `currentColor` 推导但无法表达主题语义的 `color-mix`。允许保留透明度计算，但基色必须来自思源主题变量或主题桥接变量。

处理范围包括：

- CodeMirror 编辑区、光标、选择区和活动行。
- 代码块、行号、语言菜单和操作按钮。
- 表格编辑器和表格浮层。
- 搜索匹配和当前匹配。
- 脚注提示与浮层。
- Callout、Mermaid 预览和错误状态。
- 链接、图片、任务列表及其他内联装饰。

Markdown 专属状态没有直接对应的原生元素时，使用思源已有的语义变量组合，不新增与主题脱节的固定色板。

## 兼容性边界

- 不直接把原生 Protyle 代码块 DOM 嵌入 CodeMirror。
- 不复用可能触发原生事件代理的操作类名。
- 不修改生成文件或 `lute.min.js`。
- 不改变 Markdown 文本、代码围栏解析、Lute 粘贴转换和图片本地化语义。
- 第三方主题如果覆盖 `.protyle-wysiwyg`、`.code-block`、`.hljs` 或通用思源变量，Markdown 编辑器应通过计算样式桥接获得覆盖结果。
- 第三方主题完全依赖特定 Protyle DOM 层级且不提供可计算样式时，使用思源默认语义变量作为回退，并在测试结果中记录差异。

## 验证标准

### 自动测试

- 代码块行号默认值不再固定为开启，并分别验证全局配置开启和关闭。
- 验证自动换行与连字配置能够映射到 CodeMirror 代码块样式。
- 验证语言、复制和更多操作使用思源图标精灵且未使用 Protyle 事件钩子类名。
- 验证 Lowlight 产生的 `hljs-*` 类名能够继承当前 Highlight.js 主题。
- 验证主题桥接能提取代码块、表格、浮层和 Markdown 专属语义变量，并能在主题样式变化后刷新。
- 保留现有未闭合代码围栏、Mermaid 预览、HTML 粘贴和远程图片回归测试。

### 静态验证

- 运行 Markdown 相关测试。
- 运行 `cd app && pnpm run lint`。
- 搜索 Markdown 编辑器样式中的裸颜色，逐项确认已替换或有明确保留理由。

### 应用运行时对比

实际启动思源应用，在同一主题、字号和编辑器设置下并排创建内容相同的原生代码块与 Markdown 代码块，至少覆盖：

1. 浅色默认主题。
2. 深色默认主题。
3. 一个会覆盖代码块样式的第三方主题（环境中可用时）。
4. 行号开启与关闭。
5. 自动换行开启与关闭。
6. 连字开启与关闭。
7. 已知语言、未知语言、空代码块和长行代码。
8. 悬停、聚焦、选择语言、复制和更多操作。
9. 将用户提供的结构化 Markdown 内容粘贴后生成代码块。

对每组原生与 Markdown 代码块进行截图比较，检查容器几何、字体、背景、语法颜色、行号、操作区和主题切换结果。交互验证必须确认编辑、撤销、复制、语言切换和粘贴没有回归。

## 完成条件

- Markdown 与原生代码块在相同主题和配置下没有独立的浏览器风格控件或明显视觉差异。
- Markdown 编辑器全部可见组件使用思源主题系统或计算样式桥接，不再依赖独立固定色板。
- 自动测试、Lint 和实际应用对比测试通过，并保留可复核的运行时截图证据。
