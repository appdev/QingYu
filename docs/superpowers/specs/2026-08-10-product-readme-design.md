# 轻语产品化 README 设计

## 1. 目标

将四份 README 从上游技术项目说明书重塑为轻语的产品主页。阅读者首先理解轻语为何存在、适合谁以及它如何对待内容和数据，其次才接触安装、接口与构建信息。

中文品牌名固定为“轻语”，其他语言固定为“QingYu”。轻语使用现有金色羽毛 `logo.png` 作为 README 唯一主视觉，并延续“轻语 · 明窗净几，字字轻语”的品牌母版。

## 2. 定位

轻语是一款面向长期写作、研究整理和个人知识沉淀的本地优先笔记应用。产品表达围绕四个关键词展开：安静、清晰、连接、掌控。

README 不再以“功能越多越好”为叙事方式，也不突出内核、数据库、端口和生态依赖。它应说明轻语如何让记录更轻、结构更清楚、内容更容易重新相遇，并明确数据默认由用户管理。

## 3. 信息架构

四份 README 使用一致结构：

1. 品牌首屏：缩小后的本地 logo、产品名、slogan、简短定位和语言切换。
2. 来源说明：在首屏后直接注明轻语基于思源笔记二次开发，并声明不是思源官方发行版。
3. 为什么是轻语：用短文说明产品取舍，不堆砌技术名词。
4. 核心体验：安静书写、块级连接、内容整理、数据掌控、可扩展性五个产品能力。
5. 数据与隐私：本地工作空间、加密笔记本、本地快照、S3/WebDAV/本地文件系统同步、不依赖轻语云账号、不主动发送遥测。
6. 适合人群：长期写作者、研究者、知识工作者和希望自主管理资料的用户。
7. 当前状态：明确仍在持续开发，正式分发渠道准备中，避免把思源官方安装包描述成轻语安装包。
8. 开发者入口：收束为源码结构、API、贡献指南和最小构建说明，不在首页展开 Docker、面板部署和完整 CLI 手册。
9. 上游与开源：说明与思源的关系、保留 AGPL-3.0 和原作者归属，感谢上游项目及贡献者。

## 4. 视觉与链接

- README 顶部使用 `<img alt="轻语" src="logo.png" width="128">`；非中文 alt 使用 `QingYu`。
- 删除上游功能截图、B3log 微信二维码、思源架构图、Trendshift、Twitter、Discord 和上游构建/下载徽章。
- 删除指向思源官方 App Store、Google Play、F-Droid、Microsoft Store、B3log 下载、Docker 镜像及定价页面的产品获取入口，避免品牌归属混淆。
- 保留指向思源源代码仓库的上游归属链接，以及本仓库中的 API、贡献指南、设计文档和许可证链接。
- 不生成新的横幅或伪造产品截图；当前品牌资产只有 logo 时，留白优于复用上游视觉。

## 5. 产品能力边界

README 只描述当前保留并经过项目设计确认的能力：块编辑、块引用与双向链接、Markdown 所见即所得、数据库表格、PDF 阅读与标注、网页剪藏、OCR、导入导出、本地快照、加密笔记本、S3/WebDAV/本地文件系统同步、插件/主题/模板和自托管访问。

不得继续宣称已删除的 AI/Agent、语义搜索、闪卡、知识图谱、收集箱、官方云账号、官方云同步或会员能力。不得把思源的移动端商店版本、官方云服务或发布计划表述为轻语能力。

中文基准声明：

> 轻语基于开源项目 [思源笔记](https://github.com/siyuan-note/siyuan) 二次开发，遵循 AGPL-3.0 开源协议。轻语不是思源笔记官方发行版；产品设计、功能取舍、发布与支持由轻语项目独立负责。

其他语言使用自然翻译并保持相同法律与产品含义。声明在 README 前部和“上游与开源”章节各出现一次：前部使用简短提示，末尾提供完整说明与致谢。
