# 轻语品牌口号与产品介绍设计

## 1. 目标

以“轻语 · 明窗净几，字字轻语”为中文品牌母版，替换当前“重构你的思维”体系，并让应用启动界面、关于页、Web 应用描述和各语言 README 对轻语形成一致认知。

本次不是纯字符串替换。品牌表达需要从强调“改造思维”转向营造清朗、安静、专注且由用户掌控的书写空间，同时保留轻语作为隐私优先、支持块级引用和 Markdown 所见即所得的个人知识管理工具这一事实基础。

## 2. 文案原则

- 中文品牌全称固定为“轻语 · 明窗净几，字字轻语”。
- 中文界面中产品名与口号分栏显示时，产品名使用“轻语”，口号字段使用“明窗净几，字字轻语”，由界面显式加入间隔点，避免重复产品名。
- 非中文界面保留产品名“QingYu”，口号按各语言自然表达“明窗、净几、轻声落字”的意境，不机械音译“轻语”，也不沿用“Refactor your thinking”的旧概念。
- 英文基准口号使用“QingYu · Clear windows, a quiet desk, words softly spoken.”，其他语言以该语义和中文意境共同作为翻译依据。
- 技术介绍保持可核验，不增加“零知识”“绝不上传”“完全离线”等无法由当前文案范围证明的承诺。
- README 不手工换行段落；中文使用中文标点，其他语言使用各自自然标点。

## 3. 展示入口

### 3.1 应用语言资源与关于页

更新全部 `app/appearance/langs/*.json` 的 `slogan`，每种语言使用自然翻译。关于页继续从统一语言键取值，并在产品名与 slogan 之间显示“·”。移除当前与新品牌体系无关的硬编码文案“会泽百家 至公天下”，避免出现两个竞争性的副标题。

### 3.2 Electron 启动窗口

更新 `app/electron/window.js` 中全部启动语言的 slogan。启动页本身已经分别展示产品名和口号，因此在 slogan 元素前通过固定分隔结构呈现“·”，形成与关于页相同的品牌行。

### 3.3 README

四份 README 的页首口号全部更新：中文使用完整母版，英文、日文和土耳其文使用本地化版本。

简介从单句功能定义扩展为两层：第一句传达轻语提供清朗、安静、由用户掌控的书写与思考空间；第二句准确说明隐私优先、块级引用和 Markdown 所见即所得等核心能力。功能清单、安装说明和兼容标识不借机改写。

### 3.4 Web App 元数据

更新 `app/stage/manifest.webmanifest` 的描述，使安装后的 Web App 产品介绍与 README 的英文定位一致。该文件不是 `app/stage/build/**` 生成物，允许维护。

### 3.5 安装包元数据与源码文件头

更新 `app/package.json`、Windows Appx 清单和 Linux Electron Builder 配置中的旧 slogan，安装包元数据统一使用英文完整品牌句。源码中精确等于 `// SiYuan - Refactor your thinking` 的统一文件头属于旧品牌模板，批量替换为中文品牌母版；不修改包含 SiYuan 的技术标识、上游路径、版权或兼容接口。

## 4. 检查边界

全仓检查以用户可见品牌文案为目标，覆盖旧 slogan 的大小写、简繁体和各语言翻译。历史 changelog、用户数据格式、上游仓库名、兼容协议、API 名称和技术标识不属于本次文案替换范围。

用户指南中的普通产品名不批量重写；只有直接承担口号或产品总介绍职责的内容才进入本次修改，避免对 `.sy` 指南数据做无关的大规模变更。

## 5. 验证

- 静态扫描确认可维护源码、打包元数据和文档中不再出现旧 slogan 及其现有翻译。
- 校验所有语言 JSON 可解析且语言键一致，运行 `python scripts/check-lang-keys.py`。
- 运行品牌边界测试，确保应用语言资源、Electron 启动文案、README 和 Web App 描述都采用新品牌体系。
- 按项目要求运行 `cd app && pnpm run lint`，不运行 `pnpm build` 或 `pnpm dev`。
- 检查最终差异只叠加品牌口号与产品介绍相关内容，不覆盖工作树中已有改动。

## 6. 非目标

- 不修改产品名称、应用 ID、端口、协议或打包设置。
- 不改写功能清单、许可证、版权主体、隐私政策和用户协议。
- 不承诺当前实现无法严格证明的隐私或同步能力。
- 不提交、推送、发布或部署。
