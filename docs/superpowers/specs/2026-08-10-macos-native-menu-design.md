# macOS 原生应用菜单设计

## 1. 背景与目标

轻语 Electron 主进程已经通过 `Menu.setApplicationMenu` 注册最小应用菜单，但当前只包含应用、编辑和窗口级系统操作。设置、新建文档、搜索、每日笔记、最近文档、历史、帮助等常用入口仍只存在于渲染进程的顶栏 HTML 菜单。

本次优先完善 macOS 原生应用菜单，使其遵循 macOS 常见的信息架构、跟随轻语界面语言，并将业务操作准确路由到当前获得焦点的工作空间窗口。现有顶栏菜单继续作为完整功能入口，Linux、Windows、浏览器和移动端行为保持不变。

## 2. 范围

macOS 原生菜单包含以下顶级菜单：

- 轻语：关于轻语、设置、服务、隐藏、隐藏其他、全部显示、退出轻语。
- 文件：新建文档、每日笔记、最近文档、数据历史。
- 编辑：撤销、重做、剪切、复制、粘贴、粘贴并匹配样式、全选。
- 显示：后退、前进、全局搜索、命令面板、放大、缩小、实际大小、进入或退出全屏。
- 窗口：最小化、缩放、前置全部窗口。
- 帮助：用户指南、反馈、开发者工具。

工作空间列表、保存布局及布局搜索、动态面板列表、插件菜单和其他包含自定义 HTML 或附加操作按钮的菜单不迁移。它们继续由顶栏 HTML 菜单承载。

## 3. 架构

主进程维护 macOS 原生菜单的生命周期和系统角色，渲染进程维护轻语业务命令、界面语言和工作空间状态。双方通过两个方向明确的 IPC 通道协作：

1. 渲染进程初始化完成后，向主进程发送当前窗口的菜单状态快照。
2. 主进程校验发送者属于已注册工作空间，只保留允许的标签、快捷键和布尔状态，并按窗口保存快照。
3. 当前工作空间窗口获得焦点时，主进程使用该窗口的快照重建 macOS 全局应用菜单。
4. 用户点击业务菜单项时，主进程只向当前焦点工作空间的渲染进程发送受支持的命令标识。
5. 渲染进程通过现有 `globalCommand` 或紧邻的统一分发入口执行命令。

不允许渲染进程通过 IPC 发送 Electron 菜单模板、任意角色、任意 URL 或可执行函数。主进程拥有菜单结构和命令白名单，避免把高权限菜单构造能力暴露给渲染内容。

## 4. 菜单状态与多工作空间

macOS 每个应用只有一份全局菜单，而轻语允许同时打开多个工作空间窗口。主进程按 `webContents.id` 保存每个工作空间最近一次提交的菜单快照，并在窗口 `focus` 时切换菜单状态。

快照至少包含：

- 当前界面语言对应的菜单标签。
- 支持的业务命令快捷键。
- 工作空间是否只读。
- 当前窗口是否已经完成业务初始化。

只读工作空间禁用新建文档、每日笔记、设置和数据历史等不应开放的入口。尚未收到有效快照、窗口已销毁或当前焦点不是主工作空间窗口时，业务菜单项禁用，系统角色仍保持可用。

切换轻语界面语言会触发现有配置刷新或页面重新初始化，渲染进程随后重新发送快照，主进程据此重建菜单。菜单不单独读取 macOS 系统语言。

## 5. 命令与快捷键

文件、显示和帮助菜单中的轻语业务操作复用现有命令语义，避免为原生菜单复制业务实现。新增命令标识只用于现有统一分发尚未覆盖的用户指南、反馈、命令面板和开发者工具等入口。

编辑菜单优先使用 Electron/macOS 标准 `role`，保持系统文本框、对话框输入和辅助功能行为。现有 Protyle 自定义撤销与重做快捷键处理保持不变；实施时验证原生角色不会绕过编辑器事务历史。如果验证发现行为不一致，撤销与重做菜单项改为向当前渲染进程派发编辑器命令，而不是直接使用系统角色。

业务菜单快捷键来自当前轻语键位配置，经现有快捷键转换逻辑转换为 Electron Accelerator。原生菜单成为这些命令在 macOS 上的菜单快捷键入口，渲染进程仍保留既有键盘处理以覆盖编辑器上下文和非菜单场景。测试必须确认一次按键只执行一次业务命令。

## 6. 退出与错误处理

“退出轻语”继续使用 Electron `quit` 角色，但必须经过现有 `before-quit` 保存布局、通知工作空间安全关闭和退出内核的流程。不得新增直接调用 `app.exit()` 的菜单路径。

主进程收到无效状态快照时忽略该快照并保留最近一次有效菜单。业务菜单点击时若没有有效焦点工作空间，则不发送命令。渲染进程收到未知命令时不执行任何操作。开发者工具只操作当前焦点窗口。

## 7. 文件边界

预计修改范围：

- `app/electron/main.js`：macOS 菜单构造、状态缓存、焦点切换和命令派发。
- `app/src/constants.ts`：新增受约束的菜单 IPC 通道常量。
- `app/src/boot/onGetConfig.ts`：初始化时发送菜单状态并监听原生菜单命令。
- `app/src/boot/globalEvent/command/global.ts` 或相邻的小型模块：复用并补齐业务命令分发。
- 相关测试文件：验证菜单结构、平台边界、命令白名单和状态路由。

不得重写现有 `Menu`/`MenuItem` DOM 实现，不修改富菜单结构，不新增依赖，不修改生成目录。

## 8. 验证标准

- 在 macOS 上显示“轻语、文件、编辑、显示、窗口、帮助”六组原生菜单。
- 菜单标签与当前轻语界面语言一致；重新初始化语言后菜单更新。
- 设置、新建文档、每日笔记、最近文档、数据历史、全局搜索、命令面板、后退、前进、用户指南、反馈和开发者工具正确作用于当前焦点工作空间。
- 在两个工作空间窗口之间切换时，菜单语言、只读状态和命令目标随焦点切换。
- 无有效工作空间窗口时业务菜单禁用，不抛出异常。
- 只读工作空间的写操作入口禁用。
- 退出菜单继续完成现有安全退出流程。
- Windows 和 Linux 仍使用当前最小应用菜单，不新增顶部菜单或改变窗口框架。
- 前端通过 `cd app && pnpm run lint`。
- 菜单相关自动测试通过；无法自动覆盖的 macOS 原生展示和多窗口切换在交付中列为手工验证项。

## 9. 非目标

- 不完整镜像顶栏工作空间菜单。
- 不迁移插件、块、编辑器上下文或数据库菜单。
- 不在本次实现 Linux/KDE 全局菜单。
- 不移除顶栏主菜单入口。
- 不改变用户现有快捷键配置格式。
- 不提交、推送、发布或部署修改。
