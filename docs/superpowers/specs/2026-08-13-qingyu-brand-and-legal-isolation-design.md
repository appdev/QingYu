# 轻语品牌、商标与法律边界整改设计

## 1. 背景与目标

轻语（QingYu）是基于开源项目 SiYuan 修改的独立发行版。当前代码已经完成主要应用标识、配置目录、协议、端口、内核名称和安装包名称迁移，但发行树中仍存在会让用户把轻语误认为 SiYuan 官方产品或服务的高风险路径，包括 SiYuan 官方应用更新器、官网与下载链接、上游隐私政策和用户协议、上游 Logo，以及实际随轻语挂载的 SiYuan 用户指南。

本次整改的目标是让最终发行树清晰表达轻语的独立产品身份，避免把 SiYuan 名称、Logo、发行包、官网、协议、云服务或支持渠道作为轻语自身身份使用，同时继续满足 AGPL-3.0、上游版权归属和必要的数据、插件及协议兼容要求。

本设计采用分层整改路线：彻底清除发行和用户可见表面的来源混淆风险，通过明确白名单保留版权、归属、溯源和不可变兼容标识，不进行可能破坏现有工作空间、插件 API 或旧链接读取能力的全仓机械重命名。

## 2. 产品名称与品牌图形

- 简体中文产品名固定为“轻语”。
- 繁体中文产品名固定为“輕語”。
- 其他语言的产品名固定为“QingYu”。
- `logo.png` 是轻语唯一品牌图形主源。应用图标、启动页、关于页、安装包、系统托盘和 README 使用该主源或由其确定性生成并经测试关联的派生尺寸。
- 用户界面不得继续使用 SiYuan Logo。菜单表达产品身份时使用轻语 Logo，表达导入、导出、归档或数据迁移时优先使用通用功能图标。
- `iconSiYuan` 仅在确有旧格式识别或兼容展示需要时允许保留；若没有必要消费者，则从发行资源中删除。

## 3. 用户可见品牌与服务边界

用户界面不得把“思源”“思源笔记”或“SiYuan”作为当前产品名、服务提供方、官网、下载源、更新源、协议主体或支持渠道。官网统一指向 `https://apkdv.com/`，源代码项目统一指向 `https://github.com/appdev/QingYu`。

在没有确认可用的轻语自有服务地址时，相关入口必须隐藏或安全禁用，不得伪造 URL，也不得继续使用 SiYuan、B3log、链滴或其他上游服务承接轻语的下载、反馈、隐私协议、用户协议、账号、会员、云服务或支持流程。

README、关于页、法律文档和内置指南必须以清晰但克制的方式说明：轻语基于开源项目 SiYuan 修改并遵循 AGPL-3.0；轻语不是 SiYuan 官方发行版，与 SiYuan 项目及其运营方不存在隶属、授权、认可或背书关系；轻语的产品设计、构建、发布、下载和支持由轻语开发者独立负责。

## 4. 应用更新与外部链接

在轻语自有更新服务上线前，应用版本更新能力采用关闭策略：

- 设置页隐藏“检查更新”和“自动下载更新安装包”入口。
- 内核不再查询 SiYuan 版本接口，不再解析或下载 `siyuan-*` 安装包，不再从 `release.b3log.org`、`release.liuyun.io` 或 `github.com/siyuan-note/siyuan/releases` 获取轻语应用更新。
- 即使旧配置保留了自动下载开关，运行时也不得触发上游应用更新下载。
- Electron 错误页、工作空间页和其他启动表面不再提供 SiYuan 下载链接。
- 插件、主题、图标、模板等扩展内容的集市更新不属于应用版本更新，本次不得因关闭应用更新而误伤其现有能力。
- 将来恢复轻语应用更新时，版本端点、下载地址、安装包名称、校验信息和界面开关必须由轻语自有集中配置提供，并由品牌测试覆盖，不能重新散落到语言资源或窗口配置中。

所有“官方网站”入口指向 `https://apkdv.com/`，所有“GitHub 项目”或“源代码”入口指向 `https://github.com/appdev/QingYu`。现有面向上游的反馈、帮助、下载、定价、订阅、账号和服务链接必须从轻语产品表面移除；纯粹用于代码溯源的上游 issue、pull request 和 commit 链接继续保留。

## 5. 内置轻语指南

现有四套 SiYuan 官方用户指南不进行机械品牌替换，而是重建为简体中文、繁体中文、英文和日文四套精简轻语指南。指南保持现有 `.sy` 数据格式和语言挂载机制，但内容、目录和对外链接由轻语独立维护。

每套指南仅覆盖当前代码和发行策略能够验证的内容：

1. 欢迎使用轻语及产品定位。
2. 工作空间、本地数据和备份责任。
3. 基本编辑、文档组织与搜索。
4. 导入、导出和 `.sy` 兼容边界。
5. 隐私、安全、日志和网络访问概览。
6. 插件、主题等第三方扩展的责任边界。
7. 开源许可证、上游归属、非官方关系和支持渠道。
8. 轻语隐私政策和用户协议入口。

指南不得包含或暗示轻语提供 SiYuan 账号、会员、官方云同步、云端收集箱、云端图床、SiYuan 应用商店版本、SiYuan 定价、SiYuan 下载、SiYuan 隐私政策或 SiYuan 用户协议。对于轻语当前没有提供的能力，应直接省略或明确说明不可用，不得把上游能力改名成轻语能力。

上游名称只在开源归属与兼容性页面中作事实性、必要性使用。该页面必须同时展示非官方、无隶属、无授权或背书以及独立支持声明，避免把上游名称用于轻语自身宣传。

## 6. 轻语隐私政策

项目新增轻语自己的隐私政策，不链接或套用 SiYuan 的隐私政策。隐私政策署名为“QingYu 开发者 appdev”，公开 GitHub 身份 `https://github.com/appdev`、项目地址 `https://github.com/appdev/QingYu`、网站 `https://apkdv.com/` 和联系邮箱 `lengyue@apkdv.com`，不得虚构公司、组织、办公地址或其他法律主体。

隐私政策必须依据当前代码和发布行为逐项审计后撰写，至少说明：

- 工作空间、文档、配置和日志默认存储位置及本地处理原则。
- 应用是否主动采集使用统计、诊断、安装事件、设备标识或遥测；不能将“没有发现”写成未经验证的绝对承诺。
- 用户主动启用同步、第三方扩展、网络资源、MCP、发布、WebDAV、S3 或其他外部能力时可能发生的数据传输及相应责任主体。
- 崩溃日志、系统日志和反馈材料只有在用户主动导出或发送时才由用户决定披露的边界，前提是代码审计与该表述一致。
- 第三方插件、主题、链接和外部服务不由轻语开发者控制，其各自政策独立适用。
- 数据保留、删除、迁移、安全措施、儿童隐私、跨境访问、政策变更和联系渠道。
- 开源软件与网络服务的区别，避免承诺不存在的账号或后台服务。

隐私政策提供简体中文、繁体中文、英文和日文版本，四个版本表达相同实质规则。简体中文版本作为解释分歧时的参考版本，但不得借此排除适用法律赋予用户的强制性权利。

## 7. 轻语用户协议

项目新增轻语自己的用户协议，不链接或套用 SiYuan 的用户协议。协议主体按个人开发者开源项目处理，署名和联系信息与隐私政策一致。

用户协议至少覆盖：

- 软件性质、接受方式、适用范围与最低使用资格。
- AGPL-3.0、第三方许可证、源码获取和上游版权归属。
- 用户对其内容、工作空间、凭据、同步目标、插件和备份承担的责任。
- 不得利用软件实施违法、侵权、破坏安全或损害第三方权益的行为。
- 第三方扩展、外部链接、存储服务和网络服务的独立责任。
- 软件按现状提供、无保证、责任限制、赔偿、服务或功能变更、终止以及条款可分割性。
- 轻语与 SiYuan 项目及其运营方不存在隶属、授权、认可或背书关系。

用户选择美国加利福尼亚州法作为协议设计基准，不采用强制仲裁条款。争议先通过 `lengyue@apkdv.com` 善意协商；无法解决时，协议约定由加利福尼亚州具有管辖权的州或联邦法院处理，同时明确消费者保护、冲突法和其他不可排除的强制性法律仍可能适用。由于开发者没有提供加利福尼亚州地址或注册主体，协议不得虚构专属县级法院、送达地址或公司信息，正式公开发行前应由具备相应执业资格的律师复核可执行性。

用户协议提供简体中文、繁体中文、英文和日文版本。简体中文版本作为解释分歧时的参考版本，但不得排除强制性法律权利。

项目新增独立的修改版与品牌归属声明，使用 Git 历史中可核验的首次 QingYu 仓库提交日期 `2026-08-12`，说明 QingYu 是对 SiYuan 的修改版本、修改由 `appdev` 维护、当前发行遵循 AGPL-3.0，以及上游版权继续属于各自权利人。

声明必须保留原版权信息和许可证，不得把上游代码版权改写成轻语所有，也不得宣称 SiYuan 名称或 Logo 属于轻语。README、关于页、内置指南和分发包应提供便利的许可证、修改版声明和对应源代码入口，以满足修改版显著说明和适当法律通知要求。

本次工程整改不构成法律意见，也不替代对“轻语”“QingYu”、图形 Logo、域名和其他标识进行正式商标检索。公开商业发行前仍应对目标市场进行商标和法律复核。

## 9. 兼容白名单

以下 `SiYuan/思源` 使用属于兼容、版权或溯源边界，可在用途明确且不对用户造成产品来源混淆时保留：

- Go Module、上游依赖导入路径和包名。
- `window.siyuan`、插件 API、类型名、数据库名、配置字段和序列化字段。
- 旧 `siyuan://` 与 `web+siyuan://` 链接的只读解析兼容；轻语新生成链接继续使用 `qingyu://`。
- `.sy` 数据格式、现有工作空间结构和必要的旧剪贴板桥接名称。
- 原作者版权声明、AGPL-3.0、第三方许可证和修改版归属声明。
- 指向上游 issue、pull request、commit、源代码或依赖项目的工程溯源链接。
- 开源归属页面中必要且带非官方关系说明的事实性提及。

以下使用不允许进入轻语发行和用户可见产品表面：

- 把 SiYuan 名称用于窗口标题、菜单、按钮、启动页、错误页、托盘、关于页、指南标题或当前产品能力说明。
- 把 SiYuan 官网、下载、版本接口、Release、定价、会员、账号、隐私协议、用户协议、反馈或社区当作轻语服务。
- 在轻语产品操作中展示 SiYuan Logo，或将其用于轻语格式、官网、导入导出和数据迁移入口。
- 生成新的 SiYuan 品牌协议、安装包、工作空间身份或外部产品标识。

## 10. 自动防回归与测试先行

实施采用测试先行。第一步扩展现有品牌测试，使其针对当前风险产生预期失败，再逐项实施最小整改直至测试通过。测试不得只扫描 TypeScript，而应覆盖实际发行的 HTML、JSON、Electron 配置、Go 更新器、构建元数据、图标资源和 `app/guide/**/*.sy`。

品牌审计测试至少验证：

- 应用更新器不存在 SiYuan 版本接口、上游 Release、`siyuan-*` 安装包下载和可触发的自动下载路径。
- 设置页和错误页在自有更新服务缺失时不展示应用检查更新、自动下载或上游下载入口。
- 所有用户可见官网、项目、协议和支持链接属于已批准的轻语地址集合。
- `logo.png` 是品牌主源，受批准的派生图标与其关系可重复验证，用户界面没有旧 SiYuan Logo 消费者。
- 四套内置指南不把 SiYuan 当作当前产品或服务主体，不包含上游下载、定价、账号、会员、云服务或协议链接。
- README、修改版声明和指南保留必要的 AGPL、上游归属及非官方关系说明。
- 白名单外的用户可见 `SiYuan/思源` 命中使测试失败，白名单条目必须按用途和路径显式列出，不能使用覆盖整个目录的宽泛排除。
- 旧工作空间、`.sy`、插件 API、旧块链接和旧原生 User-Agent 的必要读取兼容仍通过现有测试。
- 关闭应用版本更新不影响插件、主题等扩展集市更新。

## 11. 验证标准

完成实现后运行以下验证：

- 前端品牌与行为测试，包括先前已观察到的预期失败和整改后的通过证据。
- `python scripts/check-lang-keys.py`，确认全部语言键一致。
- `cd app && pnpm test` 或与变更范围匹配的具体 Node 测试。
- `cd app && pnpm run lint`，按项目规则完成类型检查和 ESLint。
- 与更新器关闭、兼容 URI、身份和指南挂载相关的 Go 测试；遵守项目规则，不编译或重启内核二进制。
- 对 `logo.png` 与全部派生产品图标执行尺寸、内容来源和消费者检查。
- 重新扫描所有受 Git 跟踪文件中的 `SiYuan/思源`，按“用户可见禁止、兼容白名单、版权与溯源保留”分类报告每类剩余命中。
- 冻结最终工作树后执行一次针对变更边界的集成验证，并记录无法在当前环境覆盖的 Windows、Linux、移动端和已发布服务风险。

## 12. 非目标与实施边界

- 不删除或重命名 `window.siyuan`、`.sy`、`/api/*`、Go Module、数据库字段或其他公共兼容契约。
- 不取消对旧 `siyuan://` 内容链接或旧 SiYuan 原生 User-Agent 的只读兼容。
- 不恢复或新建轻语云账号、会员、云同步、收集箱、遥测、更新后台或其他未获用户授权的新产品能力。
- 不替用户选择第三方同步或插件服务，也不代表第三方起草其政策。
- 不把工程文档中的所有上游名称机械改成轻语；只有描述当前轻语产品行为且可能造成来源混淆的内容才需要改写。
- 不提交、推送、发布或部署修改，除非用户另行明确授权。
- 本次仅处理当前 `siyuan` 仓库，不修改 Android、iOS、HarmonyOS 或其他独立仓库。
