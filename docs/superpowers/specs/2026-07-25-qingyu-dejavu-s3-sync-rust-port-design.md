# 轻语 Dejavu S3 同步 Rust 移植设计

## 状态

本设计由用户在 2026-07-25 逐项确认。它替代此前以现有轻语同步引擎、Obsidian
插件、rclone 或其他项目为主要依据的同步改造设想。

实现开始前，用户还需要审阅本文件。实现必须拆分为可独立验证的阶段，并在每个阶段
保持仓库可构建、可测试。

## 目标

在轻语中建立一套经过生产行为验证的 S3 笔记目录同步能力：将 Dejavu 的仓库格式、
同步状态机和冲突行为忠实移植为 Rust，并使用思源笔记的生产集成行为指导密钥、
仓库生命周期、后台调度和应用交互。

最终用户可以：

- 将任意已有轻语笔记目录绑定到一个远端仓库；
- 将一个远端仓库绑定到空目录或已有内容的目录；
- 在后台持续同步，同时继续使用应用和编辑不受影响的文件；
- 在发生冲突时继续使用本地版本，并在稍后查看和选择远端版本；
- 在崩溃、网络中断或另一个设备同步后安全地重新运行并收敛。

## 规范来源和优先级

设计以以下固定源码快照为基线：

- Dejavu：`siyuan-note/dejavu@8462fe30163c6e6e95ae2da832cfe76058e0e830`
- 思源笔记：`siyuan-note/siyuan@eef10568384e2e7cf547adb029ae46a72e43c287`

规范优先级如下：

1. Dejavu 源码是仓库格式、对象与分块、加密、索引与引用、远端锁、同步状态机、
   冲突结果以及安全写入顺序的依据。
2. 思源源码是密钥生命周期、仓库初始化、重置、恢复、清理、调度和应用集成行为的
   依据。
3. 本设计中已经确认的轻语差异负责将思源专用概念映射为普通文件目录和 Tauri 应用
   行为。
4. 如果自然语言说明与固定快照的可观测行为冲突，以 Go 参考实现及其测试结果为准；
   修正 Rust 实现或补充设计记录，不能自行重新解释算法。

Go/Rust 互操作是验证移植正确性的测试手段，不是要让该 Rust 模块替代思源内部的
Dejavu，也不是对外承诺一个通用的思源兼容 SDK。

轻语和 Dejavu 均使用 `AGPL-3.0-only`。翻译的源码、测试夹具和行为注释必须保留
上游来源与许可证归属。

## 明确边界

### 忠实移植的内容

- 数据实体及其序列化、哈希和标识生成方式；
- 文件对象、分块、索引、检查索引和 `refs`；
- 仓库密钥派生、加密和解密；
- 本地索引、上次同步点、云端最新索引和合并状态机；
- 文件新增、修改、删除、重命名和冲突结果；
- S3 的 Dejavu 远端布局、latest 序列引用和锁行为；
- 本地仓库清理及远端手动清理的可达性判定；
- 上游 27 个 JSON 同步场景的可观测结果。

### 使用轻语实现替换的内容

- `.sy` 块文档、SQL 索引、事务队列和 `GenerateConflictDoc`；
- `.siyuan`、Petal、思源用户指南和思源工作区专用配置；
- 思源官方云 API、配额、流量统计和缺失对象修复服务；
- 思源内核事件总线、状态栏、WebSocket 感知和插件监听器；
- 单工作区全局状态，改为轻语的一目录一仓库状态；
- Go 的包级全局锁、goroutine 组织和错误返回形式。

### 不因 Rust 或 Tauri 改变的内容

Rust 可以使用 trait、RAII、类型化错误、异步任务和每仓库对象组织代码，但不能因此
改变仓库字节格式、同步决策、冲突结果、锁时序或写入安全顺序。移植的是生产语义，
不是 Go 文件结构；同时也不能借“Rust 风格”发明新的同步算法。

### 本期不包含

- 兼容或迁移现有轻语远端同步格式和 manifest；
- 自动合并 Markdown 文本；
- 与思源工作区直接互相绑定的产品功能；
- 思源官方云缺失对象检查和修复；
- 自动执行远端仓库垃圾清理；
- 改造 WebDAV。WebDAV 在另一个设计中迁移，本期不能静默改变其行为。

## 总体架构

实现位于 QingYu monorepo 内的独立 Rust crate。它是轻语内部依赖，不作为独立通用
产品发布。

模块分为四层：

1. **Dejavu 核心层**：实体、序列化、加密、对象存储、索引、差异、合并、清理和
   仓库锁语义。该层不依赖 Tauri 或 React。
2. **云存储层**：用 trait 表达 Dejavu 所需的列举、读取、上传和删除操作；本期提供
   S3 适配器。现有轻语 S3 配置、签名和 HTTP 能力只有在不改变 Dejavu 语义时复用。
3. **轻语协调层**：目录绑定、后台任务、每仓库调度、路径级编辑协调、本地状态和
   Tauri 事件。
4. **产品界面层**：设置、同步状态、非阻塞通知、当前文件冲突标记和冲突版本选择。

现有 `remote_sync` 的 per-file manifest、同目录 `remote-conflict` 副本和旧远端对象
布局不是兼容目标。S3 迁移完成并通过验收后，由新 crate 接管 S3；旧代码只保留仍被
未迁移提供方使用的部分。

## 仓库与目录模型

### 一目录一仓库

轻语的一个笔记根目录对应一个独立 Dejavu 仓库。不同目录拥有不同的仓库 ID、本地
仓库状态、远端锁、调度时间和失败计数，可以并行同步。全局仓库密钥变更是唯一需要
跨仓库串行的操作。

### 远端布局

每个仓库使用以下外层布局：

```text
qingyu/repositories/<repository-id>/
  metadata.json
  repo/
    objects/
    indexes/
    refs/
    check/
    ...Dejavu 固定快照定义的其他仓库对象
```

`metadata.json` 只用于轻语仓库目录列表，包含格式版本、仓库 ID、显示名称和创建、
更新时间；不得包含本地绝对路径、密钥或凭据。`repo/` 内部格式严格由 Dejavu 定义。

### 本地布局

笔记根目录只包含用户文件和 `/.qingyu/syncignore`。仓库内部数据位于应用数据目录：

```text
<app-data>/sync/repositories/<repository-id>/
  repo/
  history/
  temp/
  state.json
```

- `repo/` 保存本地 Dejavu 对象、索引和引用；
- `history/` 保存同步冲突历史；
- `temp/` 保存可丢弃的当前任务临时数据；
- `state.json` 保存不参与同步的调度状态、最后结果和未处理冲突记录，不参与核心合并
  决策。

笔记目录移动后可以重新绑定同一个仓库 ID；绑定关系由轻语配置保存，仓库格式不记录
机器上的绝对路径。

## 同步数据范围

- 递归同步笔记根目录下的所有普通文件，包括 Markdown、图片、附件和用户创建的其他
  文件，不限定扩展名。
- 目录不是仓库对象；空目录不参与同步。
- 重命名表现为旧路径删除和新路径创建。
- 符号链接、设备文件和其他非普通文件不参与同步。
- 沿用 Dejavu 对隐藏路径、`.tmp` 和临时文件的内建过滤行为。
- 将思源 `/.siyuan/syncignore` 映射为 `/.qingyu/syncignore`。首次使用时创建空文件，
  它自身参与同步并作为唯一的用户目录排除配置。
- 云端更新后的 `syncignore` 在处理删除前生效，避免把新规则排除的本地文件误删。
- 不迁入思源用户指南 ID、数据库 JSON、Petal 或其他思源专用忽略规则。
- 不增加轻语自定义“只同步某个子目录”的第二套范围配置。

即使用户目录原本为空，自动创建的 `/.qingyu/syncignore` 也使初始仓库具有合法索引；
不能把完整思源调用链误判为 `ErrEmptyIndex`。

## 容量与资源边界

容量语义沿用 Dejavu 与思源的生产行为，而不是把 Rust 实现当前使用的缓冲区大小变成
轻语产品限制：

- 不为单个用户文件、当前快照或整个仓库增加轻语自定义大小上限。一个用户文件仍由
  Dejavu 分成多个块；单个明文块最大 8 MiB。
- `Index.size` 表示当前快照全部用户文件的逻辑字节数，不表示远端仓库历史对象、加密
  开销或 S3 桶实际占用空间。
- 第三方 S3 没有可移植的剩余配额查询。`available_size` 因此以既有约定返回
  `u64::MAX` 表示“未知”，而不是思源适配层使用的 2 TiB 占位值；同步状态机不得把
  “未知”解释为实测桶配额，真正的提供方配额错误由上传请求映射为安全错误。
- 只有协议上天然较小的对象使用内存上限：远端索引引用最多读取 42 字节，去除首尾
  空白后必须是 40 个小写十六进制 SHA-1 字符；远端锁 JSON 不得超过 64 KiB，轻语
  外层 `metadata.json` 不得超过 64 KiB，块对象继续使用 8 MiB 明文加 1 MiB 编码
  开销的现有边界。这些边界不是用户文件或仓库容量限制。
- `File` 元数据、`Index` 和 `CheckIndex` 不使用 64 MiB 或 512 MiB 这类轻语自定义总量
  上限。S3 响应先流式写入能力受限的任务临时文件，完整接收和验证后才导入本地仓库；
  失败、取消或崩溃留下的临时文件可安全清理，绝不发布部分对象。
- zstd 索引从受限窗口的解码流反序列化；解析后的 ID 向量仍会随快照规模增长。
  Dejavu 既有的 AES-256-GCM 单对象格式不能在不改变仓库格式的前提下分段认证，因此
  `File` 元数据在认证解密阶段仍可能占用与该元数据对象成比例的内存。这里保留格式
  兼容性，不另创 Rust 专用分片格式。

为落实这条边界，`Cloud` 区分两种读取方式：`get_bounded` 只用于引用、锁、块和外层
目录元数据；`download_to` 把可能较大的仓库对象流式写入调用方提供的临时目标。上传
同样区分小型内存对象和从已验证本地仓库对象流式读取的 `upload_from`，对应 Go S3
适配器的 `UploadBytes` 与 `UploadObject`。上传源必须能够在重试时从能力受限的本地
对象重新打开；下载一旦向临时目标写入任何字节，就不在同一目标上内部续重试，而是
失败并由任务清理临时文件。S3 适配器本身不得对成功响应执行无上限的整包读取，也
不得为较大仓库对象额外构造整包上传副本。

## 密钥与设备身份

### 本地存储

全局数据仓库密钥和稳定设备 ID 保存于不同步的
`<app-data>/local-sync.json`，使用安全原子写入。密钥以 32 字节 Base64 表示，不放入
系统 Keychain，也不写入笔记目录或远端仓库。

一套轻语安装使用一个设备 ID。不同设备必须具有不同设备 ID；用户通过导入、导出或
复制密钥，使多个设备能够读取同一远端仓库。

### 密钥生成与口令派生

行为与思源一致：

- 输入可解码为 32 字节 Base64 时，直接作为仓库密钥；
- 否则取口令 SHA-256 的前 16 个十六进制字符作为 salt；
- 使用 scrypt `N=32768, r=8, p=1, len=32` 派生密钥；
- 随机密钥使用随机口令和 salt 通过相同 KDF 生成。

### 更换密钥

更换全局密钥会清除全部旧密钥本地 `repo/`，保留笔记目录和 `history/`，并停用相关
同步绑定。旧远端仓库不会被新密钥继续使用；用户需要创建新的远端仓库。该操作必须
显式确认，并与其他仓库任务互斥。

## 统一的绑定、恢复与首次同步

核心只提供一个入口：

```text
bind_and_sync(local_notes_root, remote_repository_id)
```

它执行：

1. 验证本地根目录和远端仓库标识；
2. 打开或创建本地仓库目录，并绑定远端仓库；
3. 创建或读取 `/.qingyu/syncignore`；
4. 对当前本地目录建立 Dejavu 索引；
5. 获取远端最新索引和本地上次同步点；
6. 运行普通 Dejavu 同步和合并；
7. 持久化最新索引、上次同步点、状态和后续调度。

“启用同步”和“从云端恢复”只是不同 UI 入口，不得拥有不同的同步状态机。空目录、
已有内容的目录、空远端和已有远端都走同一入口。两个独立且非空的目录第一次绑定时，
也由普通 Dejavu 合并决定结果。

“恢复到另一个本地目录”表示用户先选择或创建目录，再调用同一个入口；它不是一种
特殊的整仓覆盖模式，也不自动替用户创建思源式工作区。

设置中的恢复弹窗提交任务后立即关闭该弹窗，设置窗口保持打开，任务交给后台服务。
恢复耗时再长也不能保持全屏遮罩或阻塞整个应用。

## Dejavu 同步状态机

每轮同步保持固定快照中的核心顺序和条件：

- 索引当前本地目录；
- 获取本地 latest、远端 latest 和 latest-sync；
- 获取缺失文件对象和分块；
- 计算本地相对 latest-sync 的变化；
- 计算云端相对本地 latest 的变化；
- 应用 Dejavu 的过滤、冲突和删除规则；
- 将远端无冲突变更恢复到工作目录；
- 本地和云端都变化时创建合并索引并上传；
- 更新远端引用、本地 latest 和 latest-sync。

第一次同步时 latest-sync 是空基线，不能发明“远端全量覆盖”或“本地全量覆盖”的
快捷分支。S3 的 `refs/latest-*` 序列行为、检查索引和引用更新顺序按固定 Dejavu
快照移植。

## 冲突行为

### 核心判定

Markdown 在核心中是普通的非 `.sy` 文件，不执行结构化内容合并。

当同一路径在本地和云端发生变更时，完整保留固定 Dejavu 快照的非对称时间规则：

- 本地 upsert 比云端 upsert 早超过 7 分钟时，忽略本地 upsert，由云端版本覆盖；
- 其他真正的双端同路径变更通常报告冲突、保留本地工作文件，并把云端版本写入同步
  历史；
- 云端过旧过滤只在 Dejavu 对应的非本地-upsert 分支发生，不能被重新解释为对称的
  “谁新谁赢”。

所有精确边界以 Go 场景测试为准。Rust 实现不增加 Markdown 三方合并，也不移植仅
适用于 `.sy` 语法树的 `GenerateConflictDoc`。

冲突发生后：

- 当前本地文件保持原样并可继续使用；
- 云端版本保存到 `<history>/<timestamp>-sync/<relative-path>`；
- 合并索引以保留下来的本地版本为准，远端随后收敛到该版本；
- 远端版本不会自动写成笔记目录中的 `*.remote-conflict-*.md`；
- 没有报告为冲突但被覆盖的旧本地版本仍由 Dejavu 本地索引历史保护，并受 180 天
  仓库保留策略约束。

固定 Go 场景另证明：两个客户端分别首次创建内容相同但时间不同的
`/.qingyu/syncignore` 时，Dejavu 仍会报告一次冲突。核心必须保留这一仓库行为；轻语
应用层把该精确受保护路径分类为内部控制文件，不生成用户冲突记录、通知、计数、路径、
标记或解决操作，避免把初始化元数据差异误报成笔记冲突。

### 轻语用户流程

同步不等待用户选择。发生冲突后：

- 弹出一次非阻塞通知；
- 当前文件显示“存在同步冲突”标记；
- 同步状态记录冲突数量、路径和时间；
- 点击标记进入本地与远端版本查看界面。

用户可选择：

- **保留本地**：不执行写入，本地已经是合并后的有效版本；
- **使用远端**：先保存当前本地版本，再用历史中的远端版本安全原子替换，并触发下一
  轮同步；
- **保留两份**：由用户选择路径把远端版本另存为普通文件，之后正常参与同步。

界面可以为 Markdown 提供只读差异比较，但不能自动决定或合并内容。冲突提示不使用
阻塞式模态窗口。

## 后台同步与实时编辑协调

后台服务拥有独立于窗口生命周期的任务。关闭设置窗口、切换应用页面或关闭发起任务
的 React 组件，不能取消已经接受的同步。

每个仓库同一时间只运行一个索引、同步、清理或重置操作；不同仓库互不阻塞。用户在
同步期间仍可以创建、编辑、重命名和删除不受影响的文件。

对即将由远端写入或删除的路径执行短时协调：

1. 获取该路径的应用级协调权；
2. 如编辑器仍有未落盘内容，先安全保存；
3. 复核文件哈希和文件身份是否仍与同步快照一致；
4. 如果已变化，放弃过期操作、重新索引，并让 Dejavu 重新计算结果；
5. 如果未变化，执行安全原子写入或删除；
6. 通知打开的编辑器重新载入远端结果并释放路径。

外部程序造成的文件变化使用相同复核。用户的新修改在当前快照之后发生时，进入下一
轮同步；不能被当前轮远端写入静默覆盖。协调只覆盖实际受影响路径，不建立整个应用的
只读状态。

## 调度与重试

轻语映射思源的三种模式：

- **自动**：文件变化、启动、退出和手动触发；
- **启动与退出**：启动、退出和手动触发，不响应普通文件变化；
- **完全手动**：只响应明确的手动触发。

自动模式默认间隔 30 秒，允许 30 秒到 12 小时。文件变化重置无变化计数并重新安排
计划；连续无变化按思源行为退避。

失败策略：

- 普通失败在 5 分钟后重试；
- 自动同步连续失败超过 7 次后暂停 64 分钟；
- 手动同步不受自动失败暂停限制；
- DNS 类错误立即额外重试一次，并以 5 分钟节流；非 Windows 平台刷新 DNS 可以是
  空操作，但重试仍保留；
- 成功后清空失败计数。

只有当前打开的笔记目录持续调度。关闭的已绑定目录不后台扫描；已经开始的首次恢复
任务可以完成，完成后若该目录未激活则停止轮询。每个仓库独立保存计划、失败计数和
最后状态。

S3 不使用思源官方云 WebSocket 感知。传输级瞬时重试可以由现有轻语 S3 客户端提供，
但不得改变 Dejavu 的仓库锁、引用顺序或把确定性冲突当成网络重试。

## 仓库锁

### 本地锁

思源只有一个数据仓库，因此 Dejavu 的 Go 包级锁表现为全局串行。轻语把该不变量
映射为每仓库锁：同一仓库串行，不相关仓库可以并行。全局密钥变更单独获取全局锁并
等待所有仓库任务结束。

### 远端锁

按 Dejavu 固定快照移植：

- 对象名为 `lock-sync`；
- 内容为带设备 ID 和时间的 JSON；
- 获取最多尝试 3 次，每次间隔 5 秒；
- 持有期间每 30 秒刷新；
- 超过 65 秒视为陈旧；
- 同一设备可以重新获得；
- 解锁删除最多重试 3 次。

第一阶段不增加 S3 条件写、ETag CAS 或租约服务。远端锁和引用更新的生产行为以
Dejavu 为准，而不是沿用现有轻语 per-file manifest 引擎的条件写方案。

## 安全写入与崩溃恢复

### 安全写入

按思源实际使用的 safer-write 顺序实现：

1. 在目标文件同目录创建随机 `.tmp`；
2. 写入全部内容；
3. `fsync` 文件；
4. 关闭文件；
5. 设置目标权限；
6. 重命名到目标路径。

Windows 因文件占用或拒绝访问导致的重命名最多重试 3 次，每次等待 200ms。不增加
父目录 `fsync`，也不宣称 Windows 重命名具备比上游更强的严格原子保证。

### 启动恢复

启动时：

- 在每个仓库 `temp/`、仓库根目录、应用数据根目录和绑定目录的直接 `.qingyu/` 中，
  只删除精确匹配 `stage-[0-9a-f]{40}.tmp` 的轻语原子写入残留；
- 不删除用户任意命名的 `*.tmp`；
- 保留正式 `repo/`、`history/` 和笔记目录。

当前实现不存在 `temp/repo` 目录，不能按该名称猜测或删除。清理只检查上述明确由轻语
拥有的直接父目录，不递归扫描笔记树，即使其他位置恰好出现同名文件也不删除。

不新增 WAL 或网络步骤续传。崩溃后下一轮重新索引并重跑同步；full-latest 等缓存可
丢弃并重建。不能发明“扫描所有 refs 并自动重下整个仓库”的恢复流程。

## 清理与保留

### 本地 Dejavu 仓库

- 第一次成功同步后异步清理；
- 两次自动清理至少间隔 6 小时；
- 之后每日调度，单次任务超时沿用思源的 12 小时上限；
- 索引默认保留 180 天；
- 当天索引全部保留，其他日期每天最多保留 2 个；
- 保留索引少于 3 个时不清理；
- 由移植后的 Dejavu `Purge` 判定不可达对象和分块。

精确选择继续服从固定思源源码：超过 180 天的索引不进入保留集合；其余索引按运行
设备的本地日历日期分组；当天全保留；旧日期固定保留当天最新索引，再在不含当天最旧
索引的 `[0, len-1)` 区间最多随机抽取 `每日保留数 * 7` 次，达到 2 个唯一索引即停止。
这里不为了 Rust 测试的确定性改成“固定首尾”或均匀采样，测试通过注入随机选择器保持
稳定。

清理按仓库独立执行。

### 冲突历史

冲突历史位于应用数据目录，默认保留 30 天，每日清理，不参与同步。它与轻语现有的
文档编辑历史是两个独立系统，不能混用保留期限或删除任务。

### 远端仓库

远端清理绝不自动执行。用户必须从独立的手动操作进入、确认，并在获得远端锁后只清理
所有远端 `refs/` 指向的索引都不可达的对象和索引。遍历、解密、引用计算、旧校验索引
和 `indexes-v2.json` 清理全部由移植后的 Dejavu `PurgeCloud` 核心能力执行，应用层不
复制仓库格式逻辑。“清理未引用数据”和“删除整个远端仓库”是两个不同操作，使用不同
确认文案。

S3 不实现思源官方云专用的缺失对象检查和修复服务。

## 重置和删除操作

轻语多仓库模型把思源相关生命周期拆成四个互不隐含的操作：

1. **重建当前本地仓库**：删除当前仓库 `repo/` 后从当前笔记目录重新索引；不删除
   笔记、历史或远端仓库。
2. **停止当前目录同步**：移除绑定和调度；不删除本地笔记或远端数据。
3. **更换全局密钥**：执行前述跨仓库密钥重置流程。
4. **删除远端仓库**：显式确认后删除目标仓库远端前缀；不隐含删除本地笔记。

任何一个操作都不能顺带执行另外三个操作。

长耗时维护操作同普通同步一样先返回已接受的后台任务，不由设置窗口或调用方等待其
完成。停止同步允许已经接受的当前任务完成，但清除绑定和持久化调度后不再接受新任务。
删除远端仓库要求该仓库已停止同步；启用中的绑定必须先由用户明确执行“停止同步”，
删除命令不能暗中代替该操作，也不能留下会重新上传到已删除前缀的调度任务。

## 状态、错误和隐私

每仓库状态至少提供：当前阶段、触发来源、开始和完成时间、最后成功时间、传输统计、
冲突数量和路径、安全错误代码、下一次计划时间。

后台进度通过 Tauri 事件发送，设置窗口和主窗口读取同一权威状态。任务不依赖任一
窗口监听器存活。

错误按阶段和安全类别表示，不能把访问密钥、密钥内容、签名、完整远端响应或用户文件
内容发送到前端和日志。失败不关闭用户正在查看的设置页，不弹出全局阻塞层；手动操作
显示一次可重试通知，自动失败按已确认的退避策略显示状态。

## 测试策略

### Go 行为基线

保留固定 Dejavu 快照的 Go 测试运行环境。首先确认：

```text
go test ./test/sync -count=1 -v
go test ./... -count=1
```

上游 `basic`、`edge`、`known-conflicts` 和 `sync-download` 四组共 27 个 JSON 场景
原样纳入，不能只把期望结果手工翻译成新的 Rust 测试。

### Rust 场景运行器

Rust 场景运行器直接读取相同 JSON，执行相同操作并校验相同的文件内容、upsert、
remove 和 conflict 计数。任何差异先与固定 Go 版本比较，不能直接修改期望让 Rust
测试通过。

### 跨语言测试

增加以下组合：

- Go 客户端创建和同步，Rust 客户端继续；
- Rust 客户端创建和同步，Go 客户端继续；
- Go 与 Rust 分别作为两个本地客户端共同使用一个测试云仓库；
- 在任一语言中崩溃或中断后，由另一语言重新运行并收敛。

这些测试证明仓库格式和状态机移植正确，但不形成面向用户的思源互操作承诺。

### 轻语补充场景

补充 Go oracle 场景后，再由 Rust 和混合运行器执行：

- 两个独立且非空的目录第一次绑定同一仓库；
- 空目录、空远端和自动创建 `/.qingyu/syncignore`；
- 子目录、空目录、附件、隐藏路径、`.tmp` 和非普通文件；
- 本地和云端同时修改 `syncignore`，以及新规则对删除的过滤；
- 同一路径新增、更新、删除和重命名组合；
- 7 分钟非对称边界；
- 同步快照后应用内编辑、外部编辑、创建、删除和重命名；
- 路径级协调期间不相关文档继续编辑；
- 冲突后本地保留、远端历史、当前文件标记和三种用户处理操作；
- 远端锁获取、刷新、陈旧接管和释放重试；
- 安全写入失败、进程中断、临时目录清理和下一轮恢复；
- 清理保留边界和手动远端清理。

### 验证门槛

每个实现阶段先运行对应 Rust 单元测试和 Go/Rust oracle，再运行仓库门槛：

```text
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml
pnpm test
pnpm typecheck:test
pnpm build
```

配置了真实 MinIO 测试服务器时，再运行 `pnpm test:s3-sync:live`。测试凭据、端点和访问
密钥不得提交。

## 验收条件

- Rust 与固定 Go 基线通过全部共享场景和跨语言场景；
- 一个已有本地目录和一个已有远端仓库可以通过普通同步合并；
- 长时间首次同步在后台运行，不关闭设置窗口、不阻塞整个应用；
- 当前快照后的用户编辑不会被远端写入或删除覆盖；
- 冲突默认保留本地，远端版本可从 30 天冲突历史查看和选择；
- 用户能从通知和当前文件标记明确知道发生了冲突；
- 仓库锁、安全写入、崩溃恢复和清理行为与本设计及上游 oracle 一致；
- S3 新仓库不依赖或生成旧轻语 per-file manifest 格式；
- 未迁移的 WebDAV 行为没有被本期改动静默改变。
