# 编辑与预览分隔线对齐

2026-11-11，对照下载的妙言 4.8.0 默认 AppKit 窗口。原版和修改前的桌面窗口均为 1120×780pt（2×截图 2240×1560px），文件夹 200、列表 300。原版内容区 618，我们为 620；差值来自两条外层分隔线的宽度计入方式，沿用上一轮侧栏结论。

## 实测规则与改动

| 行为 | 原版实测／源码补充 | 本次处理 |
| --- | --- | --- |
| 拖动左限 | 编辑区最小 200 | 从原来的 25% 改为 200 CSS px |
| 拖动右限 | 总宽度减 200，基准窗口为 418 | 改为总宽度减 200，本应用基准为 420；未改变外层分隔线占位 |
| 双击 | 自定义 300 后双击仍为 300 | 删除原先双击重置 50% 的行为 |
| 收起和恢复 | 切到编辑再返回并排，恢复 300 | 保存比例，返回并排时恢复；拖动不会自动收起一侧 |
| 窗口缩放 | 内容区 618、编辑 300，窗口从 1120 缩到 1000 后编辑 252；在 1000 时拖到 200，再缩到 960 后为 187.5 | 按比例缩放，窗口缩放不反复施加拖动下限；模式重新进入时才重新夹紧 |
| 首次并排 | 源码默认总宽度一半，最多 600 | 同规则 |
| 宽屏恢复 | 源码模式恢复时编辑区最多 1200；拖动路径没有此上限 | 区分恢复上限和拖动上限 |
| 持久化 | 原版保存 editorContentSplitPosition 比例 | localStorage 的 miaoyan-editor.content-split.v1 保存比例 |

实现位于 [content-split.ts](../src/content-split.ts)，接入 [main.ts](../src/main.ts)。原版源码为 `Views/EditorScrollView.swift` 的 `EditorContentSplitView`；静态源码用于补充宽屏规则，不代表已对原版宽屏逐项实测。

同时修复分隔线扩展点击区被右侧预览 iframe 覆盖的问题：保持可见线 1px，将点击区置于 iframe 上层，拖动期间关闭 iframe 指针接收；使用指针捕获，并在 Escape、取消、窗口失焦时恢复拖动前的比例。未调整笔记数据、编辑模型和侧栏宽度记忆。

## 滚动条

我们列表、CodeMirror 编辑区和 Vditor 预览滚动区均使用 WebKit 原生滚动条。深浅色下计算样式相同：`scrollbar-width: auto`、`scrollbar-color: auto`、`::-webkit-scrollbar` 宽度 `auto`，并继承对应 `color-scheme`；没有只给预览加粗的自定义 CSS。滑块长度随内容与可视区域比例变化，不应据此认定样式不一致。测量见 [scrollbars-before.json](../artifacts/content-split/scrollbars-before.json)。

原版 4.8.0 实际窗口同时显示 AppKit 编辑区和 WebKit 预览滚动条，宽度存在原生控件差异。本地新版源码有隐藏并排预览滚动条的路径，与下载运行包不同；本次以实际运行包为准，没有据此隐藏我们的预览滚动条。
