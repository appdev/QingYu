## 已验证和下一步

隔离冒烟使用包含不规则表格、脚注和波浪号代码围栏的样本。Latentic 挂载时原文逐字一致，勾选任务框只改一个字符。在表格前插入一段文字后，通过单元格输入及提交也只改了目标单元格。冒烟在 jsdom 中完成，当前工作未改生产代码或依赖。

下一步在轻羽的 WebView 试接，复用现有源码状态和保存流程，对比长笔记首屏、输入到绘制的 P95，并验证原生选区、中文组合输入和 Mermaid 渲染。

**对轻羽的判断。** 两种方案都有成熟项目采用。轻羽使用真实 Markdown 文件，Zettlr 和 SilverBullet 对原文保真的设计更容易对照。轻羽现有 Aa 已经具备编辑体验，已知问题是一次小编辑可能连带改写其他 Markdown。若优先修这一点，任务框可沿用分屏的一字符源码事务做局部验证。只有产品明确要求更广的原文保真，或同一负载的实际 WebView 测试显示当前 Aa 存在明显性能瓶颈，才值得评估替换。试验需同时比较输入延迟、表格与撤销、中文输入法、源文件差异。星数证明方案有实际项目采用，性能收益仍需测量。本次为源码及文档调查。 [Aa 回写](../src/rich-editor.ts#L121) · [任务事务](../src/format.ts#L48)
