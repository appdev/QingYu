# S3 笔记库同步

侧栏底部的同步状态按钮打开连接设置。填写服务地址、Bucket、区域、独立同步前缀和访问密钥。同一笔记库的各设备使用相同地址、Bucket、区域和前缀；不同笔记库使用不同前缀。

同步配置整合在「存储与同步」设置中。字段修改后自动保存，包含 AK/SK 的完整连接配置原子写入各平台应用私有配置目录下的 `s3-connection.json`，重启后自动恢复；不使用钥匙串、Keystore 或系统凭据服务。Unix 文件权限为 0600、目录为 0700，Windows 继承用户配置目录权限。配置文件位于笔记库之外，不会跟随 S3 上传。新版不读取旧钥匙串条目，旧版连接需重新填写一次；不自动删除旧条目。校验、保存和网络错误显示在按钮下方，并遮盖凭证。源码和报告不预置测试密钥。

S3 支持 Timeout（1–300 秒，默认 45）、Addressing（Path-style / Virtual-hosted-style，默认 Path-style）、TLS Verify（Verify / Skip，默认 Verify）和 Concurrent Reqs（1–16，默认 2）。「测试连接」在独立随机路径 `.connection-test/<uuid>` 检查读写、ETag 条件更新和删除，结束时尝试删除测试对象，不同步笔记或生成同步密钥；失败详情以可选择的文本块显示，并提供「复制错误信息」。清理失败也会报错，可能遗留该随机测试对象。

## 同步行为

- 未配置 S3 且未登录时，自动同步显示关闭。首次识别到登录账号或重新登录后，默认选择轻羽云存储、开启该账号的自动同步，并立即尝试一次；仍须满足服务端的套餐和邮箱校验。手动关闭后重启不自动恢复；退出登录清除账号绑定。自定义 S3 配置完整时默认开启自动同步。
- 开启自动同步后，笔记保存触发后台同步，短时间内的保存合并在一起。同步时继续编辑、切换或新建笔记，同一时刻只运行一轮，期间保存的改动安排到后续同步。保留启动、联网恢复、定时补查和「立即同步」。桌面退出前先保存本地，再给同步最多 3 秒，失败或超时直接退出；本地保存失败仍保留编辑内容。移动端进入后台时尝试同步，恢复前台且间隔已满时补一次；系统挂起期间无法保证同步。
- 手动切换提供商前显示「切换云存储提供商」确认弹窗，取消不保存更改。该弹窗是切换提醒；当前不会自动将旧提供商的历史快照迁移至新提供商。
- 复用 MDSync 1.5.1 的比较、三方合并、拉取、内容寻址、密文格式和历史记录核心，固定 commit `6f0190efd517b709ff21c4d77bcc0b221bce52b6`。
- 正文、笔记元数据和文件夹元数据按稳定 ID 独立映射。空文件夹、创建/修改时间、CRLF 和原始 Markdown 均保留。本机当前选中项不上传；被远端删除时选择剩余笔记。
- 不重叠的修改自动合并；重叠修改保留本机版本，并为远端版本创建稳定 ID 的冲突副本。列表显示「冲突副本」，正文不添加提示或冲突标记。文件夹命名/笔记移动冲突也保留双方。
- 首次两端已有数据时合并；没有共同祖先时保留双方，不按时间戳覆盖。相同内容会建立共同基线，避免下一次修改被误判为首次冲突。
- 仅原子条件写发布索引：初次 `If-None-Match: *`，更新 `If-Match: <ETag>`。412/409 重新比较和合并，最多 6 轮；没有 ETag 就停止，不降级为无条件覆盖。
- 下载与合并先在隔离文件映射中进行，校验完整性后再发布；原生端的正文、附件、元数据和同步基线在同一个文件事务中提交。网络/本机保存失败不会先替换当前内存库；同步期间笔记或附件发生变化则拒绝覆盖。不可读或损坏的笔记会阻止整库同步。
- 递归同步所选笔记库根目录内的图片和附件，包括没有被 Markdown 引用的文件及 `.attachments` 等隐藏资源目录，保留相对路径和二进制字节。排除 Markdown 笔记本体、`.miaoyan`、`.miaoyan-conflicts`、`.git` 以及符号链接；不访问根目录外的资源。附件不进行文本合并，同路径冲突保存稳定命名的双方副本；远端删除的本地附件移到 `.miaoyan/asset-trash/<uuid>/`，不永久删除。

## 存储与边界

这是针对当前笔记库模型的 MDSync 集成，不与原版 Obsidian 插件的远端目录直接混用。请使用独立前缀。逻辑文件为 `notes/<base64url-id>.md`、`library/notes/<id>.json`、`library/folders/<id>.json`、`assets/<base64url-relative-path>.bin`，云端由 MDSync 加密为内容对象、索引和历史。所有设备须升级到支持附件路径的版本；旧版遇到新路径会停止同步，避免误删。

原生 App 在「存储与同步 → 同步密码」设置或输入密码。自定义 S3 请指定一个新的独立前缀。App 的轻羽云在账号凭据授权范围内使用 `repo/qingyu/v1/vault-v2`。新库直接创建 v2 `miaoyan-key.json`，使用 PBKDF2-HMAC-SHA256 派生的密钥和 AES-256-GCM 包装随机数据密钥；远端只保存包装后的密钥和解锁参数。已有索引但密钥丢失时停止，旧前缀无需迁移。

每台 App 首次解锁后，将数据密钥保存在应用私有配置目录的 `sync-keys/` 中，供自动同步及按需附件共用。缺少缓存时后台暂停，手动设置或解锁后恢复。已有缓存的设备可重设密码，只更新密钥文件，其他已解锁设备继续同步。如果忘记密码且所有设备均失去缓存，将无法解锁。退出轻羽账号或清空自定义 S3 的两项访问凭证时，会清除对应的本机密钥缓存。网页部署端继续使用 Bucket 权限保护，请给 Web 部署设置独立前缀。

旧前缀的数据仍由 Bucket 权限保护，持有旧前缀明文密钥的人仍可解密这些对象。首次在新前缀同步成功后，旧前缀仍会保留。升级时会从可用的原连接下载待取附件。如果已修改自定义 S3 连接且原连接不可用，请先恢复原配置并点击「立即同步」取回附件，再换到新前缀。密钥信封与前缀绑定，变更前缀需要在仍能解锁时重新包装密钥。

同步基线绑定地址、区域、Bucket 和前缀。目标切换按首次合并处理；同目标索引突然消失会停止，避免误判远端删除。正文/元数据最多 4 MiB，单附件最多 64 MiB，HTTP 请求/响应最多 68 MiB。扫描本地附件时只枚举路径、大小和修改时间，哈希缓存命中时可跳过读取。拉取的附件逐个暂存到本机，事务日志只保存暂存路径和内容校验值。同步附件没有总字节上限。中断提交时会恢复原文件，远端删除的本地附件可在附件回收目录找回。

S3 的「附件下载」在桌面端默认全部下载，在手机和平板默认按需下载。按需模式会自动下载小于 1 MB 的附件，较大的附件只记录在本地占位索引中。切换 S3 连接或在同一目录使用旧版应用前，先用原连接选择「全部下载」并同步一次。S3 的远端文件格式保持不变。

图片进入可视范围后自动下载，失败时可在编辑器或图片查看器中点按重试。文件卡片会显示下载大小，点按后下载并用系统应用打开。生成或分享包含图片的笔记长图前，也会下载所用图片。在附件菜单中选择「删除未下载附件…」并确认后，下次同步将删除对应的远端附件。

Tauri 原生 HTTP 默认校验证书，TLS Verify 选择 Skip 后仅对此次配置的连接跳过证书校验。禁止跳转，只允许配置的 Bucket/前缀及该前缀的列表请求。HTTPS 之外仅允许 loopback 开发地址。历史内部留存；未增加历史浏览 UI 或移动端后台常驻服务。

## 维护与验证

MDSync 生成包在 `src/vendor/mdsync/`，包含 MIT 和依赖许可证。`node tools/mdsync/build.mjs /path/to/pinned-mdsync` 可复现提取，要求干净的固定版本 checkout；构建时只替换 manifest 发布处，加入强制条件写。`tools/mdsync/host.ts` 替换网络宿主，未引入 Obsidian UI。

本地回归：`npx vitest run --exclude '**/artifacts/**' tests/`，排除验收目录里的旧源码快照，避免重复执行旧测试。真实服务测试需显式设置 `MIAOYAN_S3_CONFIG`，指向仓库外权限为 0600 的私有 JSON；字段为界面对应的 endpoint、region、bucket、prefix、accessKeyId、secretAccessKey。不要提交此文件或将值写入报告。

`tests/sync-cloud.test.ts` 使用合成笔记，在指定测试前缀和其 `-cas` 前缀下创建、读取、条件更新、删除对象；完成后清理这些前缀。它另外准备 `-native` 前缀及私有 `native-probe.json`，用于 Rust 原生 HTTP 实测，然后由验证者清理。仅对明确可丢弃的测试空间执行。

首次原版风险复现见 `mdsync-spike-results.md`；后续正式集成的测试结果以本轮交付说明和 `artifacts/mdsync-spike/live-results.json` 为准。
