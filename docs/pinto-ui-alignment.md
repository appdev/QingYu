# Pinto 设计对齐

2026-11-13：用户确认原生设计审阅稿，授权修改产品 UI，暂不处理导入功能。

## 执行顺序

1. 工作台：栏宽、侧栏分组、列表标题、编辑器工具栏与正文排版。
2. 设置：独立窗口、手机 sheet、iPad 居中 sheet，以及外观选择与已有功能入口。
3. 菜单与弹层：复用现有行为，统一锚点、分组和视觉。
4. 定向测试、类型检查和浏览器视觉核对；记录尚未实现的原版专属状态。

串行执行：设置、工具栏与多端布局共享 DOM 和 CSS，不能安全并行改动。

## 约束

- 原生底稿是本地设计对照归档中的 `qingyu/index.html`。
- 保留原有未提交修改、笔记保存和同步逻辑。改动前文件备份及哈希在 `artifacts/pinto-ui-alignment/`。
- 不把截图作为产品界面，不伪造账户、AI、协作或历史数据。尚无后端的操作须明确不可用。
- 颜色归 `palette.json`，偏好归 `preferences.ts`，栏宽规则归 `sidebar-layout.ts`，设置导航归 `settings-view.ts`，原生窗口尺寸归 `src-tauri/src/settings.rs`。不另建并行状态体系。
- 此前偏差源于近似绘制与跨状态比较；这次的验收要求同平台、主题、尺寸和内容逐屏比较。未核对状态不能声明完全一致。

- 分享页包括协作、发送、网页和图片。图片支持预览、复制、保存及 macOS 系统分享。更多菜单提供加密和版本历史页面。
- 模板：原项目 23 个模板封面、分类、搜索、示例与关联模板。资源保留 MIT 许可。
- 当前禁用 AI 连接、账户服务、加密、协作邀请、网页发布、历史恢复和模板创建。复制文本、编辑与同步继续使用现有实现。

### 与 Pinto 仍不一致的地方

原生专属、WebView 里做不到一致的：

- 勾选动效在 Pinto 里是 Core Animation 图层，对勾沿路径描出（`strokeEnd`）。轻羽直接缩放真实的复选框，对勾用裁剪从左到右露出，笔画顺序是近似的。小点的位移、缩放和透明度在 Pinto 里是三条独立的时间曲线，轻羽合并成一组关键帧。
- Pinto 的着色强度以 30 帧每秒重绘，可以超过 1 再回落，竖线同步由页面色过渡到强调色。轻羽用 CSS 动画实现同样的时长和峰值，中间帧的颜色插值不同。
- 斜杠菜单在 Pinto 里移动选择时会向 VoiceOver 播报「名称，第几项，共几项，快捷键」。轻羽只给每一行写了对应的无障碍名称，没有主动播报。Pinto 使用系统的覆盖式滚动条，轻羽隐藏了滚动条，只保留底部渐隐。
- 此前已记录的 SF Symbols、Liquid Glass 材质、`UIMenu` 和 `UIInputView` 转场仍然适用。

功能上还没做的：

- Pinto 能显示是哪个 AI 改的，并提供「Review」进入修改记录。轻羽的外部修改没有来源信息，回执条统一写「外部」，只有「撤销」。
- Pinto 对被删掉的行会在空隙处画一条虚线，轻羽只标新增和改动的行。Pinto 在 App 内自己发起的修改会保持 2.6 秒后用 1.6 秒淡出，轻羽只实现了一直保留到下一次编辑的那一种。
- 「笔记作为应用」的嵌入组件（`NoteAppWidget`）没有实现。

### 启动、设置和独立窗口打开时不再闪出未排版页面

- 主窗口、「在新窗口打开笔记」和打开外部文档的窗口原来创建后立即显示，页面脚本和样式就绪前约 0.3 秒露出没套样式的原始 HTML，或样式已加载但笔记库还没打开的半成品界面。
- 现在这些窗口和设置窗口都以隐藏状态创建（主窗口在 `tauri.conf.json` 里设 `visible: false`；设置窗口原来只在 macOS 上隐藏、建好后立刻显示，现在各平台都等页面画好），首屏排版完成后由前端调用 `workspace_window_ready` 显示，前端逻辑在 `src/window-ready.ts`。启动时没有带文件参数就不再调用 `workspace::request`，因为它会立即显示主窗口。
- WebKit 在窗口隐藏期间不更新画面，直接显示会先贴出隐藏前画的旧内容。macOS 上第一次调用以透明度 0 显示窗口，前端等两帧画好后再调用一次，才设为不透明；前端没有回来时 1 秒后自动设为不透明。
- 兜底：页面脚本出错时 2 秒后照常显示窗口，不会一直不出现。兜底和页面通知只对还没显示过的窗口生效；窗口显示过一次后再被隐藏（例如启动后马上打开设置又关掉，macOS 上关闭设置只是隐藏），不会被重新弹出。手机上主窗口在 setup 里直接显示，没有这一步。
- 验证：macOS 验证包冷启动连拍，窗口第一帧即为完整界面，完整画面出现的时间和改动前相同；冷启动后按 ⌘, 第一次打开设置，连拍中设置窗口第一帧即为完整界面。桌面和 Android 目标 `cargo check` 通过。独立笔记窗口没有重新连拍。macOS 上关闭设置只是隐藏，再次打开时直接显示，不经过这一流程。

### 笔记列表顶部的滚动边缘与吸顶分组标题

- 原来给 `<glass-progressive-blur>` 外层另加了 `backdrop-filter` 和 `mask-image`。WebKit 会因此把外层当成背景根，组件内部的各层渐进模糊看不到下面的列表，实际只剩一层 6 px 模糊，底部渐隐反而露出清晰的文字。现在外层只负责定位，模糊全部交给组件；泛白另起一层 `.notes-scroll-wash`（只铺底色 82%，最后 14 px 淡出），同样不做背景模糊。
- 对照 Pinto macOS 的 `ListEdgeLine`：分组标题吸顶用的是 `NSTableView.floatsGroupRows`，标题固定在一处，下一组到顶时直接换上，不会把上一组往上推；滚到最顶时标题只是普通的一行，没有底带和细线。
- 轻羽桌面端把分组 `section` 设为 `display: contents`，DOM 和读屏分组（`role=group`）不变，但吸顶不再受分组范围限制。所有标题吸在同一处，最后到顶的为当前标题（`data-stuck`，浮在模糊层上、标题栏下，底边细线横贯整列），被它盖住的隐藏（`data-covered`）。
- 有标题吸顶时，标题栏和吸顶标题共用一片模糊，延伸到细线下方 14 px（`--notes-edge`）；没有时只覆盖标题栏。
- 验证：`tests/note-list-thumbnail.test.ts` 新增 1 项；macOS 验证包分三段滚动实拍，与 Pinto 截图对照。

### 菜单栏快速笔记面板（macOS / Windows / Linux）

- 对照 Pinto 的 `MenuBarExtra(.window)` 与 `MenuBarPanel`：菜单栏（Windows 通知区域、Linux 托盘）显示轻羽图标，点开一个 320 px 宽的面板。顶部是「新建笔记或搜索」输入行（44 px），不输入时列出置顶（最多 5 篇）和最近（最多 6 篇）的笔记；输入时第一行是「新建笔记“…”」，下面是匹配的笔记（标题命中在前、正文命中在后，最多 8 篇）。回车保存并在面板里显示「已保存“…”」1.8 秒，⌘回车（Windows/Linux 为 Ctrl+回车）保存后在主窗口打开；方向键选择，Esc 先清空再关闭。底栏是「打开轻羽」、设置和「退出」。面板高度随内容变化，最高 560 px。
- 面板只发请求，列表、新建、打开都由主窗口完成（`menu-bar-host.ts`），和侧栏、编辑器走同一套保存流程；同步或整理笔记库时不能新建或打开，会在面板里提示。
- 设置 › 通用 的「在菜单栏显示」（Windows/Linux 为「在系统托盘显示」）已接通，和 Pinto 一样默认打开。打开时关闭主窗口只是隐藏，不退出；面板的「退出」走主窗口原有的保存后退出流程。
- 平台差异：
  - macOS 用黑色模板图标，随菜单栏深浅色着色，面板打开期间图标保持高亮底（托盘库只在按住时高亮，由 `menu_bar.rs` 接着设置）。面板是隐藏了标题栏和红绿灯的系统窗口，保留系统圆角和阴影，不能拖动，失焦自动收起，出现在图标正下方；背景是系统 Popover 磨砂材质，输入框光标用强调色。网页透明需要 Tauri 的 `macos-private-api`（`tauri.conf.json` 的 `macOSPrivateApi`），这会让应用不能上架 Mac App Store，直接分发不受影响。面板获得焦点时应用会被激活，主窗口若在后台也会一起到前面。
  - Windows 用应用图标，左键开面板，右键出菜单；面板是无边框窗口加系统阴影，出现在图标上方并收在可用区域内。Windows 10 的无边框窗口没有圆角。
  - Linux 常见桌面的托盘（AppIndicator）只弹菜单、不报告点击位置，所以托盘菜单里放「新建或查找笔记…」「打开轻羽」「退出轻羽」，面板出现在屏幕中间。GNOME 默认需要扩展才显示托盘图标；托盘不可用时不影响其他设置。
- 验证：`tests/menu-bar.test.ts` 新增 7 项（列表规则、快速记录、主窗口应答、面板键盘与按钮），Rust 新增 2 项（面板在菜单栏下方、任务栏上方和屏幕边缘的位置）；非 macOS 分支在本机互换条件编译通过。macOS 验证包实拍了图标高亮、磨砂背景与打开的面板；打字保存、⌘回车打开和键盘操作只有自动化测试覆盖，没有在真机上完成。Windows、Linux 未实机运行。

### 新建笔记：直接打开、空白时禁用新建、「标题」提示

- 对照 Pinto 的 `RootView.newNote`：新建后直接选中并打开这篇笔记，光标在正文里，标题就是正文第一行。原来新建后会在顶部标题栏弹出改名输入框（`rename-current-note`），这个事件和监听已删除；双击标题栏和菜单里的「重命名」不受影响。
- 对照 `ListCompose.isOff` 与 `reusesForNewNote`：打开的是还没写过一个字的新笔记（正文完全为空、不在废纸篓、可编辑，判断见 `isBlankNote`）时，桌面列表顶部的新建按钮变灰禁用，悬停提示「这篇新笔记还是空的」；此时按 ⌘N、点空状态的「新建笔记」或命令面板的「新建笔记」，都只把光标放回这篇笔记，不再叠一篇空白笔记。手机上按钮不变灰，但同样复用空白笔记。以编辑区里的内容为准，打下第一个字按钮就恢复。
- 对照 `MarkdownEditor.titleHintText`：空笔记里光标所在处显示淡色「标题」，字号和粗细与笔记标题相同（桌面 28 px、手机 2em），光标不在编辑区或笔记只读时不显示。提示所在的那一行本身按标题排版（字号、粗细、行高），光标和提示同高、左上角对齐；只给提示设大字号时光标仍是正文行高，又短又偏上。
- Pinto 离开空白笔记时会直接删掉它（`Library.trash` 里的 `isBlank`），轻羽暂未做。
- 验证：`tests/new-note.test.ts` 新增 4 项；浏览器开发版实测新建后焦点在正文、无改名框、按钮禁用与恢复、⌘N 不再新建、提示样式。

### 标题栏的前进后退按钮

- 原来是最基础的 `icon-button`：图标灰色、没有按下效果、禁用时没有单独的灰度，和旁边的玻璃工具栏按钮不一样。对照 Pinto，前进后退是不带胶囊的普通工具栏按钮，所以不套玻璃胶囊，只统一效果：可用时图标为正文色，按下时出现和工具栏按钮相同的灰圆（内缩 4 px、正文色 11.5%，深色模式用浅色 16%），悬停无底色，不可用时变灰（muted、55% 不透明度，与空白笔记时的新建按钮相同）。桌面主窗口和独立笔记窗口都生效。
- 验证：`tests/note-navigation-buttons.test.ts` 新增 1 项；浏览器开发版核对可用与不可用时的颜色、按钮尺寸和按下灰圆的样式。

### 按钮统一为 Pinto 的三种按钮

- 对照 Pinto 的 `DesignSystem.swift`：按钮只有主要（`amberProminent`）、次要（`secondary`）、文字（`quiet`）三种，尺寸只有紧凑 28 / 常规 40 / 大 50（圆角 10 / 14 / 14，字号 13 / 15 / 17，半粗体）。不加描边和阴影；按下缩到 0.97（120ms）；键盘焦点是强调色 2px 描边、向外 2px。
- 轻羽原来各处各写一套：主按钮圆角有 7、8、12、999 几种，取消按钮有米色底加边框、透明加边框、灰底几种，空状态的「新建笔记」是加了描边和阴影的玻璃按钮。现在统一放在 `style.css` 的 `.primary-button`、`.secondary-button`、`.quiet-button`，尺寸用 `.button-regular`、`.button-big`，撑满一行用 `.button-wide`，危险操作加 `.destructive-button`。其他样式文件不再给按钮设底色、边框、阴影和字重（`tests/buttons.test.ts` 检查）。
- 颜色：主按钮 `--primary-fill`（浅色 #BB5B05、深色白底黑字），次要按钮 `--sand`（#F2F2F2 / #2C2C2C），悬停叠强调色 12%（深色白 8%），按下叠 20%（深色白 14%），主按钮悬停 / 按下叠黑 11% / 14%，禁用 `--button-disabled` 底和 `--button-disabled-ink` 字。
- 确认框（公开分享、新建链接的笔记）照 macOS 26 的系统提示框：宽 260、圆角 24，标题 13px 粗体、正文 13px；按钮是 28px 高的胶囊，撑满宽度上下排列，常规字重，默认按钮用强调色 #D96A06。打开时焦点在提示框本身，默认按钮不画焦点描边（原来自动聚焦会画一圈深色描边）；回车执行默认按钮，Esc 取消（`alert-dialog.ts`）。手机上按钮 44px、17px。
- 套用位置：新建文件夹和新建日程对话框、分享面板、笔记图片、上锁面板、版本历史的「恢复此版本」和「重试」、网页预览的「关闭」、登录表单（表单尺寸 40px / 15px）、空文件夹的「新建笔记」（Pinto 用次要按钮）、菜单栏面板底栏（文字按钮）。工具栏图标按钮、菜单项、分段选择、列表行不属于这三种，未改。
- 验证：`tests/buttons.test.ts` 新增 3 项；浏览器开发版核对分享确认框（宽 260、圆角 24、按钮 28px 胶囊、强调色与灰底、焦点在提示框）和分享面板主按钮（28px、圆角 10、#BB5B05、半粗体）。

### 手机上的图片查看器

- 工具栏原来把桌面的全部按钮（上一张、序号、下一张、名称、缩小、百分比、放大、还原、关闭）都放进来，按钮又放大到 40 px 且不允许收缩，在手机上超出屏宽、右半边被截掉，名称被挤成一两个字。现在手机上隐藏缩小、百分比、放大、还原和全屏整组（含两条分隔线），只留上一张、序号、下一张、名称和关闭，名称可收缩并以省略号截断。375 px 宽的视口里工具栏宽 329 px。
- 新增双指缩放：两指中点下的那一点跟着中点移动，同时按两指距离缩放（0.5–6 倍）；捏到比原尺寸小时松手弹回原样并居中；双指后剩一根手指接着拖动；用过双指的手势不当作轻点，不会误关查看器。
- 手机上图片名称放在顶部正中（白字 15px 一行，超长省略，避开状态栏），工具条只剩上一张、序号、下一张和关闭（375 px 视口下宽 185 px）；桌面上名称仍在工具条里。
- 双击放大不再依赖 `dblclick`（`touch-action: none` 下安卓 WebView 不一定派发）：在图片上 320 ms 内、30 px 内轻点两下，以点的位置为中心放大到两倍，再点两下还原。原尺寸时左右滑动图片跟手，超过 60 px 松手：当前这张滑出屏幕、下一张从另一侧滑入（共约 0.4 秒，减少动态效果时直接切换）；不够远弹回；已是第一张或最后一张时只跟三成并弹回。放大后单指拖动平移。
- 安卓把系统栏区域留作内边距，露出的是原生窗口背景色（由 `preferences.ts` 通过 `nativeAppearance` 同步，平时是纸色），查看器打开时底部露出一条白边。查看器打开和关闭时派发 `media-viewer-toggle`，打开期间原生背景换成页面压暗 62% 的颜色，状态栏和导航栏改用浅色图标。
