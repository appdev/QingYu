# 分栏拖动和缩放对齐

2026-11-11，基于 [同尺寸对比](sidebar-drag-comparison.md) 修正我们自己的列表拖动下限和窗口缩放规则，保留已有的宽度记忆及正常收起行为。

## 当前规则与改动归属

- `src/sidebar-layout.ts`、`src/sidebar-resize.ts`：列表拖动可停在 180～219，小于 180 收起；220 仅用于展开／重启时的恢复校正。文件夹栏跟随窗口宽度按比例缩放，并对齐设备像素。
- 缩放只改变显示宽度，不覆盖保存的偏好。主动拖动建立新的缩放基准；收起再展开仍恢复最近保存的宽度。取消拖动会恢复原宽度及原缩放基准。
- `src-tauri/tauri.conf.json`：桌面默认窗口的实际最小尺寸改为 960×634。原版源码的 `minSize` 是 960×600，但本机 4.8.0 的可观察窗口外框实际停在 960×634，已重复测量；本轮以相同外框尺寸对照为准。
- `src-tauri/src/file_library/workspace.rs`：独立文档窗口读取主窗口配置中的最小尺寸，避免继续使用旧的 360×420。
- 保留最近宽度记忆，不复刻原版恢复旧值或三栏拖动收起后列表重新展开的异常。笔记保存、同步和 Markdown 编辑模型未改变。

## 原生窗口对照结果

原版妙言 4.8.0，初始窗口均为 1120×780，文件夹 200、列表 300；2×截图均为 2240×1560。真实鼠标拖动后读取原生辅助功能分隔线数值。

| 检查 | 原版 | 当前版本 |
| --- | --- | --- |
| 列表停在 219 | 219 | 219 |
| 列表停在 180 | 180 | 180 |
| 窗口缩到 1000×780 | 文件夹 178.5、列表 300 | 文件夹 178.5、列表 300 |
| 窗口缩到 960×780 | 文件夹 171.5、列表 300 | 文件夹 171.5、列表 300 |
| 尝试缩到 900×500 | 停在 960×634 | 停在 960×634 |
| 放回 1120×780 | 文件夹 200、列表 300 | 文件夹 200、列表 300 |

额外验证我们的行为：列表拖到 179 后两栏正常收起；文件夹保存为 240 后拖动收起、重新展开及正常退出重开均保留 240，列表保留 300。新建独立文档窗口也实际停在 960×634，关闭后回到原主窗口；受控测试文档内容逐字不变。

结束时两个应用均保持 1120×780、栏宽 200／300，当前桌面包保持运行。原版独立分隔线与我们 border-box 的占位方式仍不同，先前列表右侧极限读数的约 2px 差异未作为本轮修复目标；编辑区保留空间不受影响。

## 本轮发现并修正的集成问题

发布版本的首次初始化发生在全局 CSS 生效前：浏览器默认 8px 页边距令容器暂时为 1104，而窗口为 1120。以容器宽度记比例基准，会在第一次拖动时将文件夹 200 错算为 203。现在统一使用窗口宽度；新增 `tests/sidebar-resize.test.ts` 模拟 CSS 清除页边距前后的容器变化，发布产物也重新验证通过。

最小高度从源码数值 600 修正为同尺寸运行对比的实际值 634。此处未推断原版额外 34pt 的具体内部约束来源，不将源码声明直接当作最终可拖动范围。

手机未重新打包或安装，Windows/Linux 原生交互及逐帧动画时长未实测。
