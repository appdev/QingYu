# Web 单密码入口设计

正式入口已经接到根目录 `login.html`、`src/login.ts` 和 API 服务。正式页复用本稿 CSS，但不包含下方的状态预览按钮；本目录仍保留为独立设计预览，不处理真实密码。部署见 [API/Web 说明](../../docs/api-service.md#web-登录与-docker-密码)。

当前品牌为“轻羽 QingYu”，页眉使用用户选定的 B 款羽毛笔 SVG：`public/brand/qingyu-mark.svg`；浏览器应用图标来自用户提供的 ICNS。

本稿使用 Hallmark 2.0.0，来源固定为 [Nutlope/hallmark@7e213cb](https://github.com/Nutlope/hallmark/tree/7e213cb6feb4ef82733bd66a0600b2e54ca0994c)。采用其 Specimen 纸面与细线语言，沿用本项目的纸白、墨绿、系统中文字体、鸟形标识和 7px 控件圆角。

用户确定的访问方式：**Docker 部署配置一个访问密码，页面只输入密码，不需要账号。** 不提供注册、用户名、API Token 输入或找回账号入口。

在仓库运行 `npm run dev`，打开 `/prototypes/web-login/`。已有开发服务时可直接打开该地址。页面底部可以切换默认、密码错误、验证中和会话过期；状态也可通过 `?state=error|loading|expired` 直接预览。

这是独立设计预览：密码仅存在于当前表单内存，页面不发送请求、不保存密码，也不伪造验证成功。本目录的 HTML/JS 不作为部署后的访问控制，也不进入 Vite 正式构建；正式页面仅复用其样式。

正式接入仍需服务端验证 Docker 配置的密码、建立和检查会话，并阻止未授权的笔记读取；仅添加一个前端密码表单不能保护远程笔记。API 的机器访问 Token 与这里的网页访问密码是不同用途。

验证记录：

- Hallmark 静态与浏览器检查：320、375、414、768、1024、1280、1440、1920 八种宽度，0 FAIL、0 REFLEX、0 WARN。
- 独立视觉评审：`ship`，默认态桌面与手机均无阻塞项；简化为单密码后，1280×800 的状态切换栏也完整显示。
- 浏览器断言：仅一个密码输入框、空值校验及焦点、密码显隐、密码错误、验证中、会话过期、无凭据请求/持久化、320px 无横向溢出、禁用脚本后内容可见。
- 项目原有 Web 构建：`npm run build` 通过，输出到项目根目录 `dist/`；该结果不代表已经接入密码验证。

没有图片或字体素材占位；后续最有价值的信息是部署后的笔记库名称，可替换通用标题。本轮没有引入新的项目依赖。
